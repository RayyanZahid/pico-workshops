## The concept

You need four things on one machine, and they talk to each other like this:

```mermaid
flowchart LR
  CC[Claude Code<br/>your agent] -->|runs| CLI[pico-cli]
  CC -->|runs| NODE[Node + Vite<br/>dev server :5301 (lab p1)]
  CC -. MCP .-> KN[pico-dev-knowledge<br/>PICO docs graph]
  CLI -->|adb| EMU[PICO OS 6 emulator<br/>Android-based]
  EMU -->|adb reverse tcp:5301<br/>http://localhost:5301| NODE
```

- **Node** serves your site: each lab's Vite dev server (ports 5301 to 5305, solutions 5311 to 5315), started for you by `node setup/launch.mjs <n> --serve`.
- The **PICO Emulator** is a PICO OS 6 device in a window, built on the Android emulator. Inside the guest, `localhost` is the guest itself, so you need a way to reach your laptop. **The course recipe: `adb reverse tcp:<port> tcp:<port>`**, which makes the guest's `localhost:<port>` tunnel to your laptop's. Then open **`http://localhost:<port>/`** in the PICO Browser. Why `localhost` and not the emulator's host alias `10.0.2.2`: a Web App needs a **secure context** (HTTPS, or `localhost`), and only a secure context can be installed or opened as a Web App. PICO's docs say to use `http://10.0.2.2:<port>/` in the emulator, but `10.0.2.2` loads but was not a secure context in our test (no install); use `localhost`. (VERIFIED 2026-09-24)
- **pico-cli** is PICO's one command line for the emulator, devices, apps, logs, screenshots, perf traces, the knowledge base and web launch. Claude Code drives everything through it.
- **Claude Code** is the agent. `pico-cli setup` gives it PICO's plugin skills and the `pico-dev-knowledge` MCP server, so its answers about PICO come from PICO's docs and not from memory.

### Why the emulator and not your headset

WebSpatial needs **PICO OS 6**. The emulator *is* PICO OS 6 (it models Project Swan). A PICO 4 Ultra runs OS 5.x, which doesn't have the WebSpatial runtime. So the emulator is the course's device. That also means a clean emulator run proves your **code** is right; it doesn't prove anything about hardware you don't have.

## Installing

**First step: get the kit.** The Academy lives in the public repo [RayyanZahid/pico-workshops](https://github.com/RayyanZahid/pico-workshops), folder `webspatial-academy/`:

```bash
git clone https://github.com/RayyanZahid/pico-workshops.git
cd pico-workshops/webspatial-academy
npm run labs:install     # one npm workspace installs every lab (SDK 2.0.0 pinned)
npm run doctor           # node setup/doctor.mjs: tells you your track (emulator or web-only)
```

This needs **Git** and **Node**. If `git` or `npm` isn't found, install them first (Windows):

```powershell
winget install --id OpenJS.NodeJS.LTS -e
winget install --id Git.Git -e
```

**After any `winget install`, close and reopen the terminal** so the new commands are on your PATH. Then check with `node --version` and `git --version`, and come back to the clone. (macOS: `brew install node@24` and `xcode-select --install`; see `setup/DEPENDENCIES.md`.) Every command in this course runs from `pico-workshops/webspatial-academy/`.

Then the rest of the toolchain. Order matters. Do it the day before.

| # | Step | Check it worked |
|---|---|---|
| 1b | **Git** (Windows: `winget install --id Git.Git -e`, then close and reopen the terminal; macOS: `xcode-select --install`). Claude Code on Windows also uses its Git Bash | `git --version` |
| 1 | **Node 20.19+ or 22.12+** (Vite 8's floor; the kit recommends 24 LTS). Windows: `winget install --id OpenJS.NodeJS.LTS -e`, then close and reopen the terminal | `node --version` |
| 2 | **Claude Code**, native installer. Windows PowerShell: `irm https://claude.ai/install.ps1 \| iex` · macOS: `curl -fsSL https://claude.ai/install.sh \| bash`. Needs a Pro, Max, Team, Enterprise or Console account (the free plan doesn't include Claude Code). Install Git first on Windows | `claude --version`, then `claude doctor` |
| 3 | **pico-cli**: `npm install -g @picoxr/pico-cli` (the unscoped `pico-cli` package is an unrelated tool) | `pico-cli --version` prints `pico-cli/0.5.x` |
| 4 | **Android Studio 2025.1.x** (the kit pins 2025.1.4.8: `winget install --id Google.AndroidStudio -e --version 2025.1.4.8`). Not the latest release: the PICO plugin can't load in newer IDEs. Add SDK Platform 35 + Sources for Android 35. | Android Studio opens |
| 5 | **PICO Spatial (Global)** plugin: Plugins > Marketplace > "PICO Spatial" > install > restart. Sign in with your PICO account. | Settings > Languages & Frameworks > PICO Spatial Tools exists |
| 6 | **Emulator image**: PICO Spatial Tools > tick the emulator under a **PICO OS 6** version (~4.3 GB download, ~12 GB installed). Or run `pico-cli emulator install`. | `pico-cli emulator doctor` reports the bundle `[ok]` |
| 7 | **Agent wiring**: `pico-cli setup --agent-tool claude-code --platform spatial --scope global --yes` | `pico-cli plugin doctor`, `pico-cli knowledge doctor` |
| 8 | **Web runtime**: `pico-cli web setup` (downloads the PICO WebSpatial browser package that `web launch` uses) | exits 0 |

Then boot it:

```bash
pico-cli doctor               # everything; add --format json for Claude
pico-cli emulator start       # starts the AVD and waits for adb
pico-cli emulator status
pico-cli device list          # note the id, usually emulator-5554
```

**On a real PICO OS 6 device** (not the course default), HTTP dev URLs are refused until you turn on the Web App debug mode. With Developer Mode on and the device on adb:

```bash
adb shell am broadcast -p com.picoxr.webappservice -a com.picoxr.webappservice.action.TOGGLE_DEBUG_MODE --ez enable true
```

(DOC, /document/web/manifest/.) Then reach your laptop over HTTPS, or with the same `adb reverse` + `localhost` recipe over USB. `10.0.2.2` only exists inside emulators.

After the emulator exists, you never need Android Studio open. It costs several GB of RAM you'll want back.

## Key commands

| Command | What it does |
|---|---|
| `pico-cli doctor [--fix] [--format json]` | Live checks across modules; `--fix` repairs the supported ones |
| `pico-cli emulator doctor / setup / install / start / status / stop` | Emulator lifecycle |
| `pico-cli web setup` | Prepares the web runtime package |
| `node setup/launch.mjs <n>` | Opens lab *n* in the emulator as a secure context: runs `adb reverse tcp:<port> tcp:<port>`, checks it with `adb reverse --list`, then opens `http://localhost:<port>/`. Refuses any target that isn't an emulator. `--serve` starts the dev server, `--solution` opens the answer, `--dry-run` shows what it would do |
| `pico-cli capture screenshot -o shots/x.png` | Screenshot of the current device |
| `pico-cli log -n 200 -l W` | Last 200 logcat lines at Warning or above |
| `pico-cli knowledge doctor / pull / server` | The PICO docs knowledge base and its MCP server |

## Common mistakes

- **Installing the newest Android Studio.** The PICO plugin accepts the 2025.1.x line only.
- **Trusting 16 GB.** PICO's 16 GB floor is for the emulator *alone*. The guest reserves ~6 GB. On a 16 GB laptop with a browser, an IDE and Claude Code open, the emulator may refuse to start with `Insufficient RAM free`, and that message goes to the terminal, **not** the emulator's log file. Run `pico-cli emulator start` in a terminal and read what it prints. If you can't free that much, lower the guest: set `hw.ramSize=4096` in `~/.pico/avd/PICO_6.0.avd/config.ini` (with the emulator stopped). At 6144 MB the emulator refused to start with 2 GB free; at 4096 it booted and ran the browser plus several web apps (VERIFIED 2026-09-24, emulator-lab).
- **Using `pico-cli web launch` to open a lab.** It rewrites `localhost` to `10.0.2.2` (flat, not a secure context, per the measurement above) and **installs a browser APK on the target first**. Wrong for WebSpatial dev, and doubly wrong for hardware. On a lending headset that's a fleet change, so don't do it without the owner's yes.
- **Re-running `pico-cli setup` while other Claude sessions are open.** Setup can upgrade the knowledge backend and kill the running `pico-dev-knowledge` MCP servers of every open session. Close other sessions first, then restart Claude Code.
- **Emulator licence.** The PICO Emulator is PICO-licensed; this workshop's attendees are cleared by PICO. Check with PICO before publishing OS screenshots outside the workshop.

## Check your understanding

1. **Inside the emulator, why open `http://localhost:5301` after `adb reverse`, rather than `http://10.0.2.2:5301`?**
   Both reach your laptop, but only `localhost` is a secure context. A Web App must be HTTPS or `localhost`, so only the `localhost` page can be installed or opened as a Web App, where WebSpatial is active. `10.0.2.2` loads but was not a secure context in our test (no install); use `localhost` (VERIFIED 2026-09-24, although PICO's docs recommend `10.0.2.2`).
2. **Your friend has a PICO 4 Ultra. Can they run today's WebSpatial app on it with the spatial effects?**
   No. The WebSpatial runtime ships in PICO OS 6. The Ultra runs OS 5.x, so the page loads as a normal flat web page.
3. **Why not just use `pico-cli web launch --url http://localhost:5301`?**
   It rewrites `localhost` to `10.0.2.2`, which lands you in the flat, non-secure case. It also sideloads a browser APK first, which is a device change you never want on a headset. Use `adb reverse` + `localhost` instead.
4. **The emulator dies right after "QEMU main loop exits abnormally". Where is the real reason?**
   On the process's stderr, in the terminal that ran it. The classic cause is `Insufficient RAM free`, which never reaches the qemu log file.
