## The concept

WebSpatial puts 3D inside a 2D layout, not the other way round. A **3D container element** is an HTML element that takes part in normal CSS layout as a flat plane, and the 3D content lives in a box in front of that plane:

```
          side view                               container = a box on a plane
   page plane                                     ┌────────────────────┐
      │                                          /│                    │
      │ ◄── width × height from CSS             / │   3D content       │  depth = --xr-depth
      │ ┌───────┐                              ┌──┼─────────────┐      │  (default: scene depth)
      │ │ model │ ─► depth (--xr-depth)        │  └─────────────┼──────┘
      │ └───────┘                              │  origin at the │ /
      │                                        │  box centre    │/
                                               └────────────────┘
```

There are two containers:

- **`<Model>`** is static. It shows a prebuilt model file (GLB or USDZ), and its API follows the web-standard `<model>` element.
- **`<Reality>`** is dynamic. You compose a scene from primitives, materials and model entities as React components.

Either can go in a **window** scene (floating in front of the page) or fill a **volume** scene, a window that behaves like a physical object with its own depth.

## The key APIs, minimal

### 1. Open a volume

```ts
import { initScene } from '@webspatial/react-sdk'

export function registerScenes() {       // call from <SpatialBoot onReady={registerScenes}>
  initScene(
    'viewer',
    prev => ({
      ...prev,
      defaultSize: { width: '0.6m', height: '0.6m', depth: '0.6m' },
      baseplateVisibility: 'automatic',   // or 'hidden'
      worldScaling: 'automatic',          // 'dynamic' = keep constant apparent size, like a window
    }),
    { type: 'volume' },                   // type is the THIRD argument in SDK 2.0
  )
}

window.open('/?scene=viewer', 'viewer')   // later, from a button
```

If the volume opens as a **flat 1280×720 window**, `initScene` ran before boot. This is exactly how p3 failed in the emulator. Register it in `<SpatialBoot onReady={registerScenes}>`; see [L2](L2.md#5-a-second-window) (VERIFIED 2026-09-24).

Volume-only options: `depth`, `worldScaling`, `baseplateVisibility`, and `worldAlignment` (`'automatic'` or `'gravityAligned'`, per the manifest schema). To make the **start** scene a volume, set it in the manifest instead (L4).

### 2. `<Model>`: show a file

```tsx
import { Model } from '@webspatial/react-sdk'

<Model
  enable-xr                                  // without this it's the flat web <model> element
  src="/models/robot.glb"
  poster="/models/robot.png"                 // shown on the backplate while loading
  autoplay loop                              // play built-in animation
  style={{ width: '100%', height: '100%', '--xr-depth': 300 } as React.CSSProperties}
  onLoad={() => console.log('model ready')}
  onError={() => console.warn('model failed')}
/>
```

- Offer formats per platform with children: `<source src="/m.glb" type="model/gltf-binary" />` and `<source src="/m.usdz" type="model/vnd.usdz+zip" />`. They're tried in order, and `onError` fires only when all have failed.
- The model is fitted to the container's width and height, keeping its proportions. Size the container, not the model.
- A ref gives you `ready` (a Promise), `currentSrc`, `entityTransform`, and animation controls (`play()`, `pause()`, `currentTime`, `playbackRate`, `duration`).
- `loading="lazy"` delays the download until it scrolls into view.

### 3. `<Reality>`: build a scene

```tsx
import { Reality, World, Material, Box, Sphere, Entity } from '@webspatial/react-sdk'

<Reality style={{ width: '100%', height: '100%', '--xr-depth': 400 } as React.CSSProperties}>
  <Material type="unlit" id="gold" color="#f5c542" />          {/* assets: outside <World> */}
  <World>                                                      {/* entities: inside <World> */}
    <Entity position={{ x: 0, y: -0.1, z: 0 }}>
      <Box width={0.2} height={0.05} depth={0.2} cornerRadius={0.01} materials={['gold']} />
      <Sphere radius={0.08} position={{ x: 0, y: 0.12, z: 0 }} materials={['gold']} />
    </Entity>
  </World>
</Reality>
```

- **Units flip here:** entity sizes and `position` are **metres**, `rotation` is **radians**, `position` is an object `{x, y, z}` (not an array). Right-handed, Y up, Z toward the user, origin at the centre of the container box.
- Primitives: `Box`, `Plane`, `Sphere`, `Cone`, `Cylinder`. `ModelAsset` + `ModelEntity` load one file and place it many times. `AttachmentAsset` + `AttachmentEntity` put live HTML on a plane in 3D. (Older `BoxEntity` and similar names are aliases.)
- No CSS on entities. To animate, update `rotation` or `position` state in `requestAnimationFrame`.

### 4. Gestures

Spatial gestures are React props on `enable-xr` elements, `<Model>` and `<Reality>` content:

| Prop | Fires | Payload |
|---|---|---|
| `onSpatialTap` | pinch-and-release (a 3D click) | `offsetX/Y/Z` (element-local px), `clientX/Y/Z` (scene px) |
| `onSpatialDragStart` / `onSpatialDrag` / `onSpatialDragEnd` | pinch-and-hold, moving | start: `offset*` / `client*`; drag: `translationX/Y/Z` (px from start) |
| `onSpatialRotate` / `onSpatialRotateEnd` | two-handed rotate | `quaternion` |
| `onSpatialMagnify` / `onSpatialMagnifyEnd` | two-handed stretch | `magnification` (1 = 100%) |

Listen through JSX only. `addEventListener('spatialtap')` on a ref isn't supported yet. Keep spatial events (`onSpatialTap` and friends) for `<Model>`, `<Reality>` entities and `enable-xr` **divs**; never put them on a `<button>`. A `<button>` with `onSpatialTap` logs `Unknown event handler property onSpatialTap` even in the PICO runtime; use `onClick` there (VERIFIED 2026-09-24).

### 5. Feature detection and units

```ts
import { WebSpatialRuntime, useMetrics } from '@webspatial/react-sdk'

const has3D = WebSpatialRuntime.supports('Model')       // also 'Reality', 'VolumeScene', 'SpatialDragEvent', ...
const { pointToPhysical, physicalToPoint } = useMetrics()  // px <-> m; inside <SpatialBoot>, spatial runtime only
```

`useMetrics` **throws** outside a WebSpatial runtime. Only render components that call it on the spatial path.

## Common mistakes

- **An `enable-xr` panel inside a volume scene.** On PICO OS 6.0.0 it failed to create (`createSpatialized2DElement failed`; lab p3's control bar is now a plain panel). Rule: inside a volume, keep 2D UI flat; put the depth in the 3D content.
- **Empty volume.** `<Reality>`/`<Model>` with `height: 100%` inside an auto-height parent is 0 px tall. Give it a real size (`100vw`/`100vh`), or give `html`/`body`/`#root` a height.
- **Volume opens as a flat 1280×720 window.** `initScene` was called at module load, before `<SpatialBoot>` booted, which is a silent no-op in SDK 2.0. Register scenes in `onReady`.
- **`<Model>` without `enable-xr`.** You get the flat web `<model>` element (or nothing, in browsers that don't implement it).
- **Mixing units.** `--xr-depth` and `--xr-back` are px. Entity sizes and positions are metres. `defaultSize` takes either (`500` = px, `"0.6m"` = metres). A `<Box width={200}>` is a 200-metre box.
- **Degrees in `rotation`.** It takes radians: `Math.PI / 2` is 90°.
- **Putting `<Material>` inside `<World>`,** or a `<Box>` outside it.
- **A 40 MB GLB.** It loads on a headset's network and GPU. Inspect with `npx @gltf-transform/cli inspect`, then simplify and compress (`gltf-transform optimize`) before you ship.
- **Testing gestures with `adb shell input`.** On the emulator, `adb input` injects a **2D touch on the flat display**, which never ray-casts into your 3D content. Test gestures by hand with the emulator window's pointer controls, and have your code `console.log` each event so you can prove it fired.
- **Nesting containers.** `<Model>` or `<Reality>` can't contain another 3D container.

## Check your understanding

1. **`<Model>` or `<Reality>` for a product viewer of an existing GLB? For a procedural bar chart?**
   `<Model>` for the file, because it's static and follows the web `<model>` API. `<Reality>` for the chart, because you compose it from `Box` entities driven by data.
2. **A `<Box width={0.2}>`: how big is it?**
   20 cm. Entity lengths are metres.
3. **You set `--xr-depth` on a `<div enable-xr>`. What happens?**
   Nothing. `--xr-depth` applies only to `<Model>` and `<Reality>`.
4. **Why did your drag handler never log when you scripted a swipe with `adb shell input swipe`?**
   That injects a 2D touch on the emulator's flat display. Spatial gestures come from a spatial ray (hand, controller or pointer), so they never reach the entity.
5. **How do you keep the page working in Chrome, where there's no 3D runtime?**
   Feature-detect with `WebSpatialRuntime.supports('Model')` (or `'Reality'`) and render a 2D fallback. `<Model>` falls back to `<model>` by itself, and `<Reality>` renders an empty placeholder box.
