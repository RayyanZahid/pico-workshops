=== L0-s1 concept
# Setup: Claude Code, Node, pico-cli and the PICO OS 6 emulator
lead: 25 minutes in the room, because the install is pre-work. 2 hours self-paced.

- **Why the emulator, not a headset:** WebSpatial needs PICO OS 6. The emulator is OS 6. A PICO 4 Ultra is OS 5.x.
- **Emulator machine:** Windows 10/11 or an Apple Silicon Mac, 16 GB RAM (32 GB is comfortable), about 40 GB free disk, an NVIDIA GeForce GTX 1060 or better.
- **Below that bar?** You take the web-only track: every lab runs flat in a desktop browser.
- **Git, and Node 20.19+ or 22.12+** (Vite 8's floor). A paid Claude plan for Claude Code.
- **Licence:** the PICO Emulator and PICO WebSpatial browser are PICO-licensed. PICO has cleared tonight's attendees to use both.

::: notes
Sources: curriculum/L0.md, SYLLABUS.md prerequisites, setup/SETUP.md. The kit recommends Node 24 LTS. Claude Code needs a Pro, Max, Team, Enterprise or Console account; the free plan doesn't include it. The full install walk-through is setup/SETUP.md; exact versions are in setup/DEPENDENCIES.md.
:::

=== L0-s2 concept
# Android Studio 2025.1.x. Exactly.
layout: warning
eyebrow: Level 0 · Setup · Read this before you install
lead: PICO's plugin only loads in Android Studio 2025.1.x. The default winget and brew installs give you 2026.1, which will not work.

- Already on a newer release? Install 2025.1.4.8 **beside** it. Don't uninstall anything.
```cmd
winget install --id Google.AndroidStudio -e --version 2025.1.4.8   # Windows
```

```cmd
bash setup/install-macos.sh --yes --emulator   # macOS
```

```expect
Android Studio → Help → About shows 2025.1.4.8. After you get the kit (L0-s5), npm run doctor confirms it.
```

::: notes
Source: setup/SETUP.md step 10 and curriculum/L0.md "Common mistakes". Say it twice: this is the install mistake that costs the most time.
:::

=== L0-s8 concept
# 16 GB of RAM? Do this before you boot.
layout: warning
eyebrow: Level 0 · Setup · The 16 GB recipe
lead: The emulator reserves 6 GB by default. On 16 GB, make room first.

- Close Chrome, Slack, Android Studio and anything else heavy.

```cmd
wsl --shutdown   # Windows
```

- With the emulator stopped, set this in `~/.pico/avd/<avd name>.avd/config.ini`:

```code
hw.ramSize=4096
```

::: notes
Close other web apps before launching a lab: at 4 GB the emulator's low-memory killer closes them. A 16 GB laptop booted this way on 2026-09-24; page rendering at 4096 is still being confirmed. Source: setup/SETUP.md step 13 and the kit CLAUDE.md. Windows path: %USERPROFILE%\.pico\avd\PICO_6.0.avd\config.ini. "Insufficient RAM free" goes to stderr only, never the emulator log. labs/EMULATOR-RESULTS.md measured about 2 GB of free commit on a 16 GB laptop with Chrome, WSL and node running, against 6,144 MB needed.
:::

=== L0-s9 step
# Boot the emulator
action: Start the PICO OS 6 emulator from a terminal and wait for adb.

Run it in a terminal you can see. If it dies, the real reason is printed there and nowhere else.

```cmd
pico-cli emulator start
```

```expect
The emulator window opens and the command returns once adb is ready.
"Insufficient RAM free" means go back to the 16 GB recipe.
```

```prompt
Start the PICO emulator with `pico-cli emulator start`, wait for adb readiness, then run `pico-cli emulator status` and `pico-cli device list` and tell me the device id to use for the rest of the day.
```

img: ../assets/emulator/00-emulator-home-launcher.png | The PICO OS 6 emulator after boot: the home launcher floating in a virtual bedroom, with Browser, Settings, Viewer, Files and Media Player tiles and a status bar

::: notes
If start fails for any reason other than RAM, run `pico-cli emulator doctor` first. On Windows, bare `adb` may not be on PATH after an Android Studio install: the full path is %LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe. launch.mjs and snap.mjs find it automatically.
:::

=== L0-s12 checkpoint
# Checkpoint: you are set up when...
lead: Every box ticked, or a written reason next to it.

- `npm run doctor` names your track, and `pico-cli doctor` is clean or explained.
- `pico-cli emulator status` shows a running emulator, or you're on the web-only track.
- You know your device id (usually `emulator-5554`).
- You can say why the emulator opens `localhost` through `adb reverse`, not `10.0.2.2`.

`adb reverse` makes the emulator's `localhost:<port>` your machine's port, and `localhost` is a secure context. 10.0.2.2 loads but was not a secure context in our test (no install); use localhost.
