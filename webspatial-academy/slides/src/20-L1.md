=== L1-s1 concept
# Hello Spatial: your first WebSpatial app
img: ../assets/emulator/03-lab1-web-app-card-lifted.png | Lab p1 installed as a Web App in the emulator: a glass window with the enable-xr card as its own panel, badge "Web app · WebSpatial on"
lead: A website becomes an app in the room. You keep writing HTML and CSS.

- **Not WebXR.** WebXR gives you a canvas and a head pose, and you draw every pixel. WebSpatial gives the OS your HTML to render next to other apps.
- **Window scene:** a 2D panel for GUI. It keeps the same apparent size, so text stays readable.
- **Volume scene:** a box with real depth, in metres, for showing an object.
- **React is required.** The SDK hooks React's JSX runtime. A static .html file never passes through it.
- **No packaging on PICO OS 6.** Run the dev server, open the URL, install it as a Web App from the address bar.

::: notes
From curriculum/L1.md. The WebXR vs WebSpatial table is worth drawing on a whiteboard if the room is mixed. visionOS is the other platform, and it needs @webspatial/builder and a Mac.
:::

=== L1-s2 concept
# A browser tab is flat. A Web App has depth.
layout: compare
eyebrow: Level 1 · Hello Spatial · The one idea
lead: WebSpatial only switches on inside PICO OS 6's Web App Runtime. The button in the address bar is the door.

## Browser tab
- Your page, in a PICO Browser tab.
- **Flat.** `enable-xr` and `--xr-*` do nothing here.
- `display-mode` is `browser`.

## Web App
- Install it from the address bar: the monitor icon, titled Install app on OS 6.0.0 (PICO's docs call it Open as standalone app).
- **Depth.** WebSpatial switches on: elements lift, `window.open` opens new windows.
- Needs a secure URL: `localhost` via `adb reverse`.
- `display-mode` is `standalone` or `minimal-ui`.

::: notes
PICO's docs (assets/pico-docs/WEB-APP-RUNTIME.md, from developer.picoxr.com/document/web/webspatial/ and /install-free/): "In the Web App Runtime of PICO OS 6, any WebSpatial API used in your page source is automatically activated." The button only appears when the URL falls inside a Web App's manifest scope. No install needed for development, and no WebSpatial Builder on PICO. webspatial.dev calls the same button "Run as a standalone app"; PICO's label is "Open as standalone app".
:::

=== L1-s3 concept
# What the Web App needs
eyebrow: Level 1 · Hello Spatial · The door only opens if...
lead: No install, no depth. Two things decide whether the page can become a Web App.

- **A secure URL.** In the emulator open `http://localhost:<port>/` through `adb reverse`; `node setup/launch.mjs <n>` sets this up. 10.0.2.2 loads but was not a secure context in our test (no install); use localhost.
- **A manifest with the 4 required fields:** `name` (or `short_name`), `icons`, `start_url`, `display`. Link it with `<link rel="manifest" href="/app.webmanifest">` and serve it as JSON (`application/manifest+json`).

To see the adb reverse it will run, without running it:

```cmd
node setup/launch.mjs 1 --dry-run
```

```code
{ "name": "Hello Spatial", "start_url": "/", "display": "minimal-ui",
  "icons": [ { "src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png" } ] }
```

::: notes
MEASURED on the OS 6 emulator (emulator-lab + labs-builder, 2026-09-24): http://10.0.2.2:<port>/ loads but reports isSecureContext=false, beforeinstallprompt never fires, and the page stays a flat tab. localhost through adb reverse is a secure context, and Lab 1 installed as com.picoxr.webapp.localhost.* with depth. PICO's docs say 10.0.2.2; the measurement overrides them for this workshop (assets/pico-docs/WEB-APP-RUNTIME.md section 3, kit CLAUDE.md, setup/launch.mjs). Manifest rules: developer.picoxr.com/document/web/manifest/ via WEB-APP-RUNTIME.md section 4. PICO requires display (it's optional on some other platforms). `scope` decides which URLs count as the app, and so where the button shows. On a real PICO OS 6 device HTTP needs Developer Mode plus a debug broadcast; not tonight's concern.
:::

=== L1-s4 step
# Show which runtime you're in
img: ../assets/media/p1-solution-hello.png | Lab p1 in desktop Chrome, the flat fallback: the enable-xr card drawn flat and the runtime badge reading "Browser tab · flat"
action: Put a badge on the page that says browser or webapp.

```code
function getWebRuntime() {
  if (window.matchMedia('(display-mode: browser)').matches) return 'browser';
  if (window.matchMedia('(display-mode: standalone)').matches
      || window.matchMedia('(display-mode: minimal-ui)').matches) return 'webapp';
}
```

```expect
In a browser tab the badge says browser, and nothing pops out: that's expected.
Installed as a Web App it says webapp, and enable-xr elements lift.
```

::: notes
From developer.picoxr.com/document/web/install-free/. Also works in CSS: @media (display-mode: standalone) { ... }. Recommended in every lab so people can see at a glance why nothing pops out.
:::

=== L1-s5 concept
# The whole recipe, in four lines
eyebrow: Level 1 · Hello Spatial · SDK 2.0.0, as the labs pin it
lead: No vite-plugin. No XR_ENV. One bundle; PICO is detected at runtime from the user agent.

```cmd
npm i @webspatial/react-sdk@2.0.0 @webspatial/core-sdk@2.0.0 --save-exact
```

```code
// 2. tsconfig: "jsxImportSource": "@webspatial/react-sdk"   AND   vite.config.ts:
react({ jsxImportSource: '@webspatial/react-sdk' })
// 3. main.tsx
<SpatialBoot><App /></SpatialBoot>
// 4. index.html
<link rel="manifest" href="/app.webmanifest">
```

After the four steps below, mark something: `<div enable-xr>` with `position: relative`, `--xr-back: 80` (px) and `--xr-background-material: translucent`.

::: notes
Source: labs/VERSIONS.md and the p1/p2 lab READMEs. @webspatial/vite-plugin 1.0.1 aliases the SDK to /web, which 2.0 removed, so builds fail with it. Proven on the OS 6 emulator by emulator-lab (2026-09-24): lab 1's solution, installed as a web app, reported UA ... PicoWebApp/0.4.0 ... WebSpatial/1.5.0, react-sdk 2.0.0, and spatialized its enable-xr card (the screenshot on "Make it pop out").
:::

=== L1-s7 step
# Route JSX through the SDK
action: Set jsxImportSource in two places: the tsconfig that holds "jsx", and vite.config.ts.

```code
"jsx": "react-jsx",
"jsxImportSource": "@webspatial/react-sdk"
```

```code
react({ jsxImportSource: '@webspatial/react-sdk' })
```

```expect
Every <div> you write in JSX now goes through WebSpatial's createElement, which is what understands enable-xr and --xr-back.
If enable-xr does nothing later, suspect this step first.
```

::: notes
In Vite's template the tsconfig is tsconfig.app.json (curriculum/L1.md); the labs use a single tsconfig.json. The vite.config line comes from the kit CLAUDE.md: Vite 8 transforms with oxc and ignores esbuild.jsxImportSource, so without it every enable-xr goes inert with no error. curriculum/L1.md only shows the tsconfig half.

=== L1-s8 step

action: Wrap the app in <SpatialBoot> and link a PWA manifest.

```code
createRoot(document.getElementById('root')!).render(
  <SpatialBoot>
    <App />
  </SpatialBoot>,

```

The manifest needs `display` set to `standalone` or `minimal-ui`, plus a 1024 maskable icon with no transparency. Without a valid manifest the browser can't install it as a Web App.

::: notes
<SpatialBoot> renders nothing while it loads and has no fallback prop, so put loading UI outside it. Add onError={e => console.error(e)} if the emulator shows a blank page.

=== L1-s11 concept
# Never point web launch at a real headset
layout: warning
eyebrow: Level 1 · Hello Spatial · The one rule
lead: pico-cli web launch is for the emulator only.

- It **installs a 336 MB PICO WebSpatial browser APK** on the target before it opens anything.
- It **rewrites localhost to 10.0.2.2**, which exists only inside the emulator and isn't a secure context there either.
- Both are right for the emulator and wrong for a headset. A PICO 4 Ultra runs OS 5.x and has no WebSpatial runtime anyway.
- On this emulator image it also **fails** (`INSTALL_FAILED_UID_CHANGED`): the browser is a system app it can't update.
- Use `node setup/launch.mjs <n>`: `adb reverse` plus localhost, and it **refuses any target that isn't an emulator**.

::: notes
Source: kit CLAUDE.md "Emulator and pico-cli rules" (pico-cli 0.5.0, source-read) and TROUBLESHOOTING.md. The lending headsets on the table are someone else's fleet: installing an APK on one is a change to their device.
:::
