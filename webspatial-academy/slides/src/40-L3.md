=== L3-s1 concept
# 3D and volumes
img: ../assets/emulator/10-lab3-volume-web-app.png | Lab p3 installed as a Web App in the emulator: the main window turned to glass, with a lifted card showing the avocado model preview (avocado.glb, 2.4 MB, 682 triangles) and an Open in 3D button that opens the 0.6 m volume
lead: WebSpatial puts 3D inside a 2D layout. A 3D container takes part in CSS layout as a flat plane, and its content lives in a box in front of it.

- **`<Model>`** shows a prebuilt GLB or USDZ file. Its API follows the web `<model>` element.
- **`<Reality>`** composes a scene from primitives, materials and model entities as React components.
- **Volume scene:** a window that behaves like a physical object, sized in metres.
- **Units flip:** `--xr-depth` is px, entity sizes and positions are metres, rotation is radians.

::: notes
30 minutes. Teach <Model> first; <Reality> is optional stretch (SYLLABUS run of show). Unverified per L3.md: that <Model> and <Reality> render in PICO OS 6's runtime on the emulator. Say so.
:::

=== L3-s2 step
# Open a volume with a model
action: Ask Claude Code for a 'viewer' volume that shows your GLB.

```prompt
Add a volume scene called 'viewer' (defaultSize 0.6m on all three axes, registered in <SpatialBoot onReady={registerScenes}>, not at module load) that shows public/model.glb with <Model enable-xr> plus a poster image, onLoad and onError handlers. Open it from a button on the main page with window.open('/?scene=viewer', 'viewer'). In a desktop browser the button should still open a normal tab.
```

```code
// call from <SpatialBoot onReady={registerScenes}>
export function registerScenes() {
  initScene('viewer', prev => ({
    ...prev,
    defaultSize: {
      width: '0.6m', height: '0.6m', depth: '0.6m',
    },
  }), { type: 'volume' })  // 3rd argument
}
```

::: notes
Inside a volume, keep 2D UI flat; put the depth in the 3D content: an enable-xr panel inside a volume failed to create on PICO OS 6.0.0 (createSpatialized2DElement failed). VERIFIED (assets/emulator/WALKTHROUGH.md): in SDK 2.0, initScene() does nothing until <SpatialBoot> has finished. It returns undefined and throws nothing, so a call at the top of main.tsx is lost: window.open gets the default config and a type: 'volume' scene opens as a flat 1280x720 window. Register scenes from <SpatialBoot onReady={...}>. Without enable-xr, <Model> is the flat web <model> element. The model fits the container's width and height: size the container, not the model.
:::

=== L3-s4 step
# Make it respond to a drag
img: ../assets/media/p3-solution-viewer-volume.png | The viewer scene's own page opened in desktop Chrome: the volume's content, flat
action: Wire spatial drag and tap onto the model.

```prompt
Make the model follow a spatial drag: on onSpatialDragStart remember the start, on onSpatialDrag apply translationX/Y/Z (px) through a style transform, and on onSpatialTap reset. Tell me which event carries which field and what I have to test by hand because adb cannot inject a spatial ray.
```

- `onSpatialTap`: `offsetX/Y/Z` and `clientX/Y/Z`
- `onSpatialDrag`: `translationX/Y/Z`, px from the start
- `onSpatialRotate`: `quaternion` · `onSpatialMagnify`: `magnification`

```expect
Each handler logs to the console, so you can prove it fired.
```

::: notes
adb shell input injects a 2D touch on the emulator's flat display. It never ray-casts into 3D content. Test gestures by hand with the emulator window's pointer.
:::
