=== L2-s1 concept
# Spatialize a website
lead: The headline level. You don't rebuild the site. You pick a few elements and give them a Z axis.
img: ../labs/_shots/p2-start.png | The lab's starting site, Swanfest, in a desktop browser: a hero, three feature cards and a schedule. This is what you spatialize.

- **Mark** the elements you want lifted with `enable-xr`.
- **Lift** them toward you with `--xr-back`.
- **Glass:** make the window transparent and give lifted elements a translucent material.
- **Split:** move secondary content into its own window with `initScene` + `window.open`.

X and Y stay plain CSS. Every Z property is ignored in an ordinary browser, so the desktop site doesn't change.

::: notes
45 minutes: 10 of concept, 35 of lab. Success is a before and an after screenshot. The mental model from L2.md is "2D containing 3D".
:::

=== L2-s4 step
# Read what --xr-back does
img: ../assets/emulator/21-lab2-web-app-spatial.png | The result of --xr-back in the emulator: lab p2's lifted feature cards stand forward of the glass window and overhang its bottom edge
action: Check the card CSS against the three rules.

```code
.card {
  position: relative;   /* required: relative, absolute or fixed */
  --xr-back: 40;        /* px only, one decimal allowed */
}
```

- It's an inset like `top`, but on Z: the distance to the plane behind the element.
- **Don't nest `enable-xr` inside `enable-xr`.** On PICO OS 6.0.0 the nested one never rendered. Lift one or the other.
- Units are **px**, not metres. `"0.1m"` is not valid here.

```expect
If a card doesn't move: it's missing enable-xr, or it has no position.
```

=== L2-s6 step
# Split off a second window
action: Open a details window from the Learn more button.

```prompt
Add a second window scene called 'details' with initScene (defaultSize 480 x 600), registered in <SpatialBoot onReady={registerScenes}> (not at module load), open it from the Learn more button with window.open('/?scene=details', 'details'), route ?scene=details to a Details component in main.tsx, and make sure it still opens as a normal tab in a desktop browser.
```

```code
// register after boot, or it's a no-op
const registerScenes = () =>
  initScene('details', prev => ({
    ...prev,
    defaultSize: { width: 480, height: 600 },
  }), { type: 'window' })

<SpatialBoot onReady={registerScenes}>

// on click; 2nd arg = scene name
window.open('/?scene=details', 'details')
```

```expect
Learn more opens a second window (the OS may size it like the main window). In desktop Chrome it opens a tab.
```

::: notes
In a second window, don't wrap the page in enable-xr; the window is already glass. Keep floating panels small and few. initScene must run before window.open, and after boot. VERIFIED (assets/emulator/WALKTHROUGH.md): in SDK 2.0, initScene() does nothing until <SpatialBoot> has finished. It returns undefined and throws nothing, so a call at the top of main.tsx is lost: window.open gets the default config and a type: 'volume' scene opens as a flat 1280x720 window. Register scenes from <SpatialBoot onReady={...}>. The name must match the second argument. The OS treats defaultSize as a request.
:::
