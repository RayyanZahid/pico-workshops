## Three facts before you start {#intro-s2}

*id: intro-s2 · level: intro · step: 2 · kind: concept*

Each one has cost someone an hour. Say them out loud.

- **WebSpatial requires React.** It works by replacing React's JSX runtime. There is no plain-HTML path today.
- **WebSpatial needs PICO OS 6.** The emulator is PICO OS 6 and has the runtime built in, so you open a URL and nothing gets packaged. A PICO 4 Ultra runs OS 5.x and shows a flat page.
- **The SDK just moved to 2.0.** `@webspatial/react-sdk` 2.0.0 is what the labs pin. We teach the 2.x API (`<SpatialBoot>`). Older guides use `@webspatial/vite-plugin` and `XR_ENV=avp`, which belong to 1.x.

> **Speaker notes:** Source: curriculum/SYLLABUS.md "Three facts before you start". If someone has a 1.x project, point them at curriculum/TROUBLESHOOTING.md#version-drift and move on.

## How the pieces talk {#intro-s4}

*id: intro-s4 · level: intro · step: 4 · kind: concept*

Four things on one machine. Claude Code drives all of them.

- **Node + Vite** serves your site on a port per lab (5301 for lab 1).
- **PICO OS 6 emulator** is a PICO device in a window, built on the Android emulator.
- **pico-cli** is PICO's one command line for the emulator, apps, logs, screenshots and perf.
- **Claude Code** runs pico-cli and the dev server, and asks the `pico-dev-knowledge` MCP about PICO docs.

The emulator opens your site at `http://localhost:<port>/`, mapped to your machine with `adb reverse`. `node setup/launch.mjs <n>` does the mapping for you.

## 16 GB of RAM? Do this before you boot. {#L0-s8}

*id: L0-s8 · level: 0 · step: 8 · kind: concept*


- With the emulator stopped, set this in `~/.pico/avd/<avd name>.avd/config.ini`:

## Hello Spatial: your first WebSpatial app {#L1-s1}

*id: L1-s1 · level: 1 · step: 1 · kind: concept*

A website becomes an app in the room. You keep writing HTML and CSS.

- **Not WebXR.** WebXR gives you a canvas and a head pose, and you draw every pixel. WebSpatial gives the OS your HTML to render next to other apps.
- **Window scene:** a 2D panel for GUI. It keeps the same apparent size, so text stays readable.
- **Volume scene:** a box with real depth, in metres, for showing an object.
- **React is required.** The SDK hooks React's JSX runtime. A static .html file never passes through it.
- **No packaging on PICO OS 6.** Run the dev server, open the URL, install it as a Web App from the address bar.

## A browser tab is flat. A Web App has depth. {#L1-s2}

*id: L1-s2 · level: 1 · step: 2 · kind: concept*

WebSpatial only switches on inside PICO OS 6's Web App Runtime. The button in the address bar is the door.

## Browser tab
- Your page, in a PICO Browser tab.
- **Flat.** `enable-xr` and `--xr-*` do nothing here.
- `display-mode` is `browser`.

## Web App
- Install it from the address bar: the monitor icon, titled Install app on OS 6.0.0 (PICO's docs call it Open as standalone app).
- **Depth.** WebSpatial switches on: elements lift, `window.open` opens new windows.
- Needs a secure URL: `localhost` via `adb reverse`.
- `display-mode` is `standalone` or `minimal-ui`.

> **Speaker notes:** PICO's docs (assets/pico-docs/WEB-APP-RUNTIME.md, from developer.picoxr.com/document/web/webspatial/ and /install-free/): "In the Web App Runtime of PICO OS 6, any WebSpatial API used in your page source is automatically activated." The button only appears when the URL falls inside a Web App's manifest scope. No install needed for development, and no WebSpatial Builder on PICO. webspatial.dev calls the same button "Run as a standalone app"; PICO's label is "Open as standalone app".

## What the Web App needs {#L1-s3}

*id: L1-s3 · level: 1 · step: 3 · kind: concept*

No install, no depth. Two things decide whether the page can become a Web App.

- **A secure URL.** In the emulator open `http://localhost:<port>/` through `adb reverse`; `node setup/launch.mjs <n>` sets this up. 10.0.2.2 loads but was not a secure context in our test (no install); use localhost.
- **A manifest with the 4 required fields:** `name` (or `short_name`), `icons`, `start_url`, `display`. Link it with `<link rel="manifest" href="/app.webmanifest">` and serve it as JSON (`application/manifest+json`).

To see the adb reverse it will run, without running it:

```bash
node setup/launch.mjs 1 --dry-run
```

```tsx
{ "name": "Hello Spatial", "start_url": "/", "display": "minimal-ui",
  "icons": [ { "src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png" } ] }
```

> **Speaker notes:** MEASURED on the OS 6 emulator (emulator-lab + labs-builder, 2026-09-24): http://10.0.2.2:<port>/ loads but reports isSecureContext=false, beforeinstallprompt never fires, and the page stays a flat tab. localhost through adb reverse is a secure context, and Lab 1 installed as com.picoxr.webapp.localhost.* with depth. PICO's docs say 10.0.2.2; the measurement overrides them for this workshop (assets/pico-docs/WEB-APP-RUNTIME.md section 3, kit CLAUDE.md, setup/launch.mjs). Manifest rules: developer.picoxr.com/document/web/manifest/ via WEB-APP-RUNTIME.md section 4. PICO requires display (it's optional on some other platforms). `scope` decides which URLs count as the app, and so where the button shows. On a real PICO OS 6 device HTTP needs Developer Mode plus a debug broadcast; not tonight's concern.

## Show which runtime you're in {#L1-s4}

*id: L1-s4 · level: 1 · step: 4 · kind: step*

**Do this:** Put a badge on the page that says browser or webapp.

```tsx
function getWebRuntime() {
  if (window.matchMedia('(display-mode: browser)').matches) return 'browser';
  if (window.matchMedia('(display-mode: standalone)').matches
      || window.matchMedia('(display-mode: minimal-ui)').matches) return 'webapp';
}
```

You should see:

```text
In a browser tab the badge says browser, and nothing pops out: that's expected.
Installed as a Web App it says webapp, and enable-xr elements lift.
```

## The whole recipe, in four lines {#L1-s5}

*id: L1-s5 · level: 1 · step: 5 · kind: concept*

No vite-plugin. No XR_ENV. One bundle; PICO is detected at runtime from the user agent.

```bash
npm i @webspatial/react-sdk@2.0.0 @webspatial/core-sdk@2.0.0 --save-exact
```

```tsx
// 2. tsconfig: "jsxImportSource": "@webspatial/react-sdk"   AND   vite.config.ts:
react({ jsxImportSource: '@webspatial/react-sdk' })
// 3. main.tsx
<SpatialBoot><App /></SpatialBoot>
// 4. index.html
<link rel="manifest" href="/app.webmanifest">
```

After the four steps below, mark something: `<div enable-xr>` with `position: relative`, `--xr-back: 80` (px) and `--xr-background-material: translucent`.

> **Speaker notes:** Source: labs/VERSIONS.md and the p1/p2 lab READMEs. @webspatial/vite-plugin 1.0.1 aliases the SDK to /web, which 2.0 removed, so builds fail with it. Proven on the OS 6 emulator by emulator-lab (2026-09-24): lab 1's solution, installed as a web app, reported UA ... PicoWebApp/0.4.0 ... WebSpatial/1.5.0, react-sdk 2.0.0, and spatialized its enable-xr card (the screenshot on "Make it pop out").

## Never point web launch at a real headset {#L1-s11}

*id: L1-s11 · level: 1 · step: 11 · kind: concept*

pico-cli web launch is for the emulator only.

- It **installs a 336 MB PICO WebSpatial browser APK** on the target before it opens anything.
- It **rewrites localhost to 10.0.2.2**, which exists only inside the emulator and isn't a secure context there either.
- Both are right for the emulator and wrong for a headset. A PICO 4 Ultra runs OS 5.x and has no WebSpatial runtime anyway.
- On this emulator image it also **fails** (`INSTALL_FAILED_UID_CHANGED`): the browser is a system app it can't update.
- Use `node setup/launch.mjs <n>`: `adb reverse` plus localhost, and it **refuses any target that isn't an emulator**.

## 3D and volumes {#L3-s1}

*id: L3-s1 · level: 3 · step: 1 · kind: concept*

WebSpatial puts 3D inside a 2D layout. A 3D container takes part in CSS layout as a flat plane, and its content lives in a box in front of it.

- **`<Model>`** shows a prebuilt GLB or USDZ file. Its API follows the web `<model>` element.

- **Units flip:** `--xr-depth` is px, entity sizes and positions are metres, rotation is radians.

## Where everything sits in Z {#L4-s2}

> **Speaker notes:** Run the launch command from the kit root in a second terminal, then install the example as a Web App. Source: examples/README.md (examples-scout). Every standalone sample repo is SDK 1.x with @webspatial/vite-plugin, which fails to build on 2.0; only the apps/* fixtures in the webspatial-sdk monorepo are 2.0. @webspatial/starter 0.1.0 scaffolds ^1.5.0. The labs win where these disagree. webspatial-vite-min is desktop-verified (build clean, 0 console errors on all 3 pages, __webspatialsdk__ 2.0.0) and not yet run on the emulator; its Model swaps in the p3 avocado GLB on PICO. It shares labs/node_modules, so run npm run labs:install first. Repos without a license are linked, not vendored. Community apps: webspatial.dev/showcase.
